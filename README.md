# Teamytime

Локальное приложение для командной работы агентов через GigaCode CLI.
У каждого участника своя роль, модель и продолжаемая сессия. Пользователь наблюдает
диалог, принимает решения и добавляет уточнения во время выполнения задачи.

## Запуск

Нужен **Node.js 22.16.0 или новее**, в том числе разрешённая корпоративная версия.
Используется встроенный `node:sqlite`; предупреждение об экспериментальном статусе
SQLite в некоторых версиях Node ожидаемо.

Сборка и установка зависимостей выполняются **внутри закрытого контура**.
Работаем с исходниками и зависимостями из настроенного корпоративного npm-реестра.
Пакет `tsx` исключён из проекта и lock-файла. На машине с установленным Node.js
и настроенным корпоративным npm-реестром достаточно выполнить:

```sh
npm start
```

Откройте **http://127.0.0.1:4318**. Сервер останавливается через `Ctrl+C`. На macOS
можно запускать двойным щелчком
[`scripts/start-teamytime.command`](scripts/start-teamytime.command).

`npm start` и запуск двойным щелчком автоматически устанавливают необходимые
зависимости при первом запуске, собирают исходники на том же компьютере, затем
запускают сервер. При ошибке установки или сборки запуск останавливается.
Для обновления остановите сервер через `Ctrl+C` и выполните:

```sh
git pull --ff-only && npm start
```

Затем обновите страницу браузера. Изменения `package.json`, `package-lock.json`,
проектного `.npmrc`, платформы или ABI Node.js автоматически вызывают повторную
установку. При неизменных зависимостях npm не вызывается. Если необходимый пакет
удалён, установка повторяется. Отметка успешной установки хранится в
`node_modules/.teamytime-install.json`; одновременная подготовка двух запусков блокируется.

Установка использует `npm ci --omit=dev --include=prod --include=optional --no-audit --no-fund`.
Основной реестр должен быть заранее настроен корпоративными средствами: проверьте
`npm config get registry`. Автоустановка останавливается, если указан публичный
реестр npmjs. Проект не меняет реестр, авторизацию и другие настройки npm.
При отсутствии доступа к корпоративному реестру установка завершится ошибкой
с выводом npm в терминале.

Для отдельной сборки доступен `npm run build`; готовая папка `dist` исключена из Git.
`esbuild` находится в обычных зависимостях и нужен для сборки на машине запуска.
Для разработки и проверки типов установите инструменты отдельно через
`npm ci --include=dev`. `npm run typecheck` проверяет типы без создания сборки;
`npm run dev` запускает режим разработки. Автоподготовка обычного `npm start`
при необходимости выполняет чистую установку без инструментов разработки.

`tsx` проекту больше не нужен:
скрипты сборки и тестирования написаны на обычном JavaScript, TypeScript компилирует esbuild.
Расширение исходников React `.tsx` обозначает TypeScript с JSX и не является
зависимостью от одноимённого пакета.

Если установка другого пакета завершится ошибкой, нужен полный вывод `npm ci`:
по нему можно определить зависимость для замены или согласованного добавления
в реестр. Готовый архив не используется как замена проверке разрешённости библиотек.
Настройки реестра проект не меняет. Ошибка `ERR_MODULE_NOT_FOUND` сама по себе
показывает отсутствие пакета локально, но не причину отсутствия.

`npm run dev` запускает режим разработки. После изменения интерфейса обновите
страницу. Перезапуск сервера прерывает активные ходы без автоматического повторения.

## Первый сценарий

1. В «Команды и роли» настройте 2–8 участников: имя, роль, модель и личные инструкции.
   Можно назначить одну роль нескольким участникам, создать свои роли и копии шаблонов.
2. Выберите ведущего, параллельность (1–4), лимит ходов (4–100) и контрольные точки.
   Изменения шаблона применяются к новым задачам; созданная задача хранит снимок команды.
3. Создайте задачу в режиме **Демо**. Ответы заранее заданы; реальная задача не
   выполняется. Демонстрация использует тот же планировщик и протокол действий.
4. Отправляйте сообщения участнику или уточнения всей команде. Уточнение повышает
   версию требований. Счётчики показывают доставку и успешное завершение обработавших
   сообщение ходов, а не доказательство содержательного соблюдения требований моделью.
5. Во вкладках «Решения» и «Результат» доступны предложения, итог и скачиваемые материалы.

## Подключение GigaCode

На той же машине установите CLI и выполните вход через обычный `gigacode` в терминале.
В «Команды и роли → Подключение» укажите команду или абсолютный путь к исполняемому
файлу без shell-аргументов. Проверка наличия файла не проверяет авторизацию.

Поле модели участника — `default` или поддерживаемый CLI идентификатор для `--model`.
Запрошенная модель, значение из инициализации и модель ответа хранятся раздельно:
в ваших логах они различались. После настройки создайте задачу в режиме **GigaCode**.
Пустой рабочий каталог создаётся автоматически; явно указанный должен существовать.

Адаптер рассчитан на формат **GigaCode 26.8.41**:

- отдельный процесс на ход; сначала `--session-id UUID`, далее `--resume UUID`;
- `--chat-recording`, `--append-system-prompt`, `--output-format stream-json`,
  `--include-partial-messages`, `-p`;
- обсуждение: `--approval-mode=plan`; выполнение: `--approval-mode=auto-edit`
  с `--allowed-tools run_shell_command`;
- `--exclude-tools agent save_memory exit_plan_mode ask_user_question`;
- `--max-session-turns 12`, таймаут, отмена группы процессов на POSIX;
- обязательный успешный `result` и завершение процесса, учёт накопительного usage
  по разнице, отсутствие дублей текста и внутренних рассуждений в публичном диалоге.

`auto-edit` позволяет менять файлы и выполнять команды. `--allowed-tools` не является
эксклюзивным списком всех инструментов. Teamytime не создаёт ОС-песочницу. Режим `plan`
и исключения инструментов ещё нужно проверить на целевой версии CLI.

## Сотрудничество и восстановление

Ответ агента — JSON с публичной репликой `message` и массивом `actions`. Планировщик
проверяет схему, получателей, полномочия ведущего и актуальность версии требований.
`send` адресует сообщение и добавляет ход получателя; публичная реплика сама по себе
никого не запускает. Порядок ролей не зашит в планировщик.

Доступны поручения, темы, решения, текстовые артефакты и запрос завершения со ссылками
на сообщения коллег. Если есть рецензент, нужно его актуальное сообщение. Завершение
ждёт пустой очереди и закрытых тем/решений. Последующий ответ сбрасывает прежний итог.
Ссылки на сообщения пока не заменяют независимую проверку утверждений участников.

Одна сессия выполняет один ход одновременно. В процессе максимум четыре активных
участника; на канонический рабочий каталог — один участник с правом выполнения.
Это не ограничивает процессы вне Teamytime и не заменяет ограничения инструментов CLI.

Новые требования действуют со следующего хода. Устаревший ответ сохраняется с
отметкой, его управляющие действия отбрасываются. После устаревшего хода исполнителя
приложение ставит задачу на паузу для проверки возможных изменений файлов.

«Пауза» завершает активные ходы и сохраняет очередь, «Остановить» отменяет задачу.
После сбоя пользователь выбирает повтор или пропуск неопределённых ходов.
Флажок «Продолжать после повтора или пропуска ошибочных ходов» включён по умолчанию:
очередь запускается после восстановления всех ошибочных ходов, если лимит не исчерпан.
При выключенном флажке нужно нажать «Продолжить». Повтор может повторно изменить файлы;
автоматического отката нет. Новая ошибка снова останавливает работу.

В поле сообщения Return отправляет сообщение, Shift+Return вставляет новую строку.
Пустые сообщения, повторные нажатия во время отправки и подтверждение ввода IME не отправляются.

Ответ остаётся JSON с `message` и `actions`; вступление, заключение и Markdown-ограждение
вокруг одного объекта допустимы. Несколько ответов или некорректные действия не исполняются.
Отказ отдельного инструмента при успешном результате CLI сохраняется как предупреждение
рядом с ответом; он не подтверждает выполнение отклонённой проверки и не расширяет права роли.
Действие `{"type":"continue","reason":"оставшаяся работа"}` ставит следующий ход того же
участника в очередь. Оно соблюдает паузу, ограничения параллельности и общий лимит ходов.
Само обещание «начинаю проверку» без этого действия продолжение не запускает; инструкции
требуют выполнить работу до ответа или явно запросить продолжение.

Данные хранятся в `.teamytime/teamytime.sqlite`, создаваемые рабочие каталоги — в
`.teamytime/workspaces/`. Нативную историю хранит GigaCode; для переноса продолжаемых
сессий нужны оба хранилища. Путь CLI и таймаут берутся из текущих настроек перед ходом.
Таймаут задаётся в настройках → «Подключение» → «Таймаут одного хода, секунд»;
по умолчанию — 600 секунд (10 минут). При обновлении прежние 180 секунд однократно
заменяются на 600; остальные сохранённые значения остаются прежними. Изменение
действует со следующего хода, включая повтор, и не меняет таймер уже работающего хода.
Если указанная модель отсутствует в каталоге GigaCode, ход один раз повторяется без
`--model`, с моделью по умолчанию CLI. В диалоге появляется предупреждение, обе попытки
попадают в отчёт. Замена выполняется только при отказе до инициализации сессии;
общий таймаут хода сохраняется. Настройки участника не перезаписываются. Ошибки входа,
сети или выполнения не вызывают такую замену.
События фиксируются в SQLite до публикации SSE. Обновление браузера не останавливает
процессы. После перезапуска сервера незавершённые ходы не повторяются автоматически.

Сервер слушает только `127.0.0.1`, проверяет Host/Origin и не предназначен для публикации
в сети. Один процесс владеет каталогом данных. Другой порт/каталог (подходит Zsh):

```sh
PORT=4319 TEAMYTIME_DATA_DIR=/абсолютный/путь/к/данным npm start
```

## Проверки и границы первой версии

### Как передать результат тестового запуска

Открой нужную задачу и нажми **«Скачать отчёт ↓»** под заголовком. Получится один файл
`teamytime-run-<ID>.json.gz` — его можно передать целиком для разбора, без копирования
диалога и команд в терминале. К файлу достаточно добавить, что ожидалось и что пошло
не так; для визуальной ошибки — скриншот.

Отчёт доступен во время работы, после завершения, ошибки, остановки и перезапуска
приложения. Он содержит снимок одной задачи: задание, команду, модели, сообщения,
ходы, решения, результаты, последние 5000 событий приложения и журналы GigaCode.
Для каждого нового хода сохраняются параметры запуска, stdout/stderr, время записей,
код/сигнал выхода и итоговый статус. Эти данные автоматически хранятся в
`.teamytime/teamytime.sqlite` (или в каталоге `TEAMYTIME_DATA_DIR`). Дополнительные
зависимости и отдельное включение логирования не нужны.

Потоки фиксируются по завершённым строкам; последняя незавершённая строка сохраняется
при выходе CLI. В каждом потоке хода остаётся до 512 записей и 512 КиБ последних
данных. Число удалённых записей указано в `droppedEntries`; строки больше 64 КиБ
заменяются отметкой. Параметры и итог хода хранятся также отдельно от stdout/stderr.
Исходные логи старых ходов восстановить нельзя — их ID перечислены в `missingTurnIds`.

В диагностической копии маскируются известные поля токенов/паролей, ссылки авторизации,
домашний и рабочий каталоги. Внутренние рассуждения и содержимое частичных дельт
пропускаются; полные ответы и вызовы инструментов берутся из `assistant`/`result`.
Отчёт содержит текст задачи и результаты: произвольные секреты в свободном тексте
могут остаться. Файлы рабочего каталога, другие задачи, переменные окружения и
хранилище авторизации в отчёт не собираются.

Для автоматизированного сбора доступен `GET /api/runs/<ID>/report`. Это gzip-сжатый
JSON с `format: "teamytime-run-report"` и `formatVersion: 1`.

### Автоматические проверки

Проверка типов и логики автоподготовки без сборки приложения и загрузки пакетов:

```sh
npm run typecheck
npm run test:startup
```

Полный набор проверок, включающий сборку, выполняется внутри контура:

```sh
npm run check
python3 -m unittest discover -s tests
```

Тесты покрывают парсер, UTF-8, usage, создание/продолжение/отмену тестового CLI,
очередь, блокировки, устаревшие ответы, контрольные точки, лимит ходов, восстановление
SQLite, HTTP и повторную доставку SSE. Сквозной демозапуск проверен в браузере.

В присланном командном запуске разные модели отвечают, но обнаружены отказы инструментов,
ответы с текстом перед JSON и превышение таймаута. Обновлённый обработчик принимает все
пять завершённых ответов из этого отчёта. Новый живой запуск с исправлениями и действием
`continue` нужно проверить на целевой машине: локально GigaCode отсутствует.
При некорректных действиях ход останавливается, публичный текст сохраняется;
автоматического исправляющего вызова нет.

Остаются в плане: ACP/потоковый stdin, граф зависимостей решений, отдельные ветки
обсуждений, файловый diff, автоматические проверки результата, бюджет токенов/стоимости
и перенос нативных сессий. Первая целевая платформа — macOS; другие ОС не проверены.
